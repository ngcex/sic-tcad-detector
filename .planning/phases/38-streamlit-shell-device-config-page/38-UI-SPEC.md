# Phase 38 — UI Design Contract

> Visual and interaction contract for the Streamlit shell + device config page. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Framing note:** The target is **Streamlit**, not a React/shadcn web app. Every visual token below is expressed in Streamlit's actual primitives (`.streamlit/config.toml [theme]`, `st.set_page_config`, sidebar widgets) so the executor can apply it directly. Streamlit natively owns heading sizes, line-heights, and most micro-spacing; this contract declares only what the app can and should control. shadcn gate is **not applicable** (Python stack — no React/Next/Vite). This is the FIRST UI phase; the tokens, page structure, empty-state guard, and sidebar contract established here are inherited by Phases 39–43.

## Design System

| Property          | Value                                                                                                                                                                                                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tool              | none (Streamlit-native theming via `.streamlit/config.toml`)                                                                                                                                                                                                       |
| Preset            | not applicable                                                                                                                                                                                                                                                     |
| Component library | none — Streamlit built-in widgets only (`st.number_input`, `st.selectbox`, `st.radio`, `st.info`, `st.warning`, `st.json`, `st.navigation`, `st.Page`)                                                                                                             |
| Icon library      | Material Symbols via Streamlit `icon=":material/…:"` shorthand (built into Streamlit 1.58; no dependency). Emoji fallback acceptable.                                                                                                                              |
| Font              | Streamlit default sans-serif (**Source Sans Pro**) for UI text; **monospace** (`font="monospace"` in theme, or `st.code`/`st.json`) for all numeric scientific readouts (doping values, config summaries) so scientific-notation values align and are unambiguous. |

**Rationale:** A scientific/engineering tool for a physics research group. Prioritize clarity, information density, and correctness signaling (units, warnings) over decorative polish. No custom CSS/HTML injection in this phase — Streamlit-native primitives only.

## Spacing Scale

8-point scale is the convention for the layout Streamlit lets the app control (`st.columns` gap arguments, explicit spacers, custom container padding). Streamlit owns default widget-to-widget vertical rhythm — do not fight it with CSS hacks.

| Token | Value | Usage in this phase                                                                                                                                   |
| ----- | ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| xs    | 4px   | (reserved) inline icon gaps                                                                                                                           |
| sm    | 8px   | (reserved) compact grouping inside a widget cluster                                                                                                   |
| md    | 16px  | Default — matches Streamlit's native widget vertical gap; use `gap="small"`/default on `st.columns`                                                   |
| lg    | 24px  | Section breaks in the sidebar between field groups (achieved with `st.sidebar.header` + a `st.sidebar.divider()`), and `gap="medium"` on `st.columns` |
| xl    | 32px  | Major main-panel section separation (`gap="large"` on `st.columns`)                                                                                   |
| 2xl   | 48px  | (reserved) page-level top spacing                                                                                                                     |
| 3xl   | 64px  | (reserved)                                                                                                                                            |

**What the app controls this phase:** sidebar field-group separation (dividers/headers), and `st.columns` gaps in the main panel config-summary. Everything else is Streamlit-native rhythm.

Exceptions: none.

## Typography

Streamlit owns heading sizes and line-heights natively (rendered from `st.title`/`st.header`/`st.caption`) on a 16px root. The **Size** column below lists the px values Streamlit's default Source Sans Pro theme **already renders** for each role — these are declared as a contract for the checker, **not** as overrides. Do **not** hand the executor pixel line-heights requiring CSS; do **not** override these sizes.

**Single section-heading primitive:** `st.header` (28px) is the ONLY primitive used for section-heading roles in this phase — both main-panel sections and sidebar field-group headers (`st.sidebar.header`). `st.subheader` (24px) is **not used** anywhere in Phase 38, so the scale has no dual-size heading row. **Downstream Phases 39–43 must follow this same single primitive** (`st.header` for every section heading) to keep the shared scale at 4 sizes.

| Role             | Streamlit primitive               | Size (Streamlit default, not an override) | Weight            | Line Height   |
| ---------------- | --------------------------------- | ----------------------------------------- | ----------------- | ------------- |
| Page title       | `st.title(...)`                   | 36px (2.25rem)                            | semibold          | ~1.2 (native) |
| Section heading  | `st.header(...)`                  | 28px (1.75rem)                            | semibold          | ~1.2 (native) |
| Body / label     | widget labels + `st.write`        | 16px (1rem)                               | regular           | ~1.6 (native) |
| Caption / helper | `st.caption(...)`                 | 14px (0.875rem)                           | regular           | ~1.5 (native) |
| Numeric readout  | `st.json` / `st.code` (monospace) | 14px (0.875rem)                           | regular monospace | ~1.5 (native) |

Sizes declared: exactly 4 real sizes — **14, 16, 28, 36**. All are Streamlit-native defaults; the app applies **no** font-size or line-height overrides.

Weights used: exactly 2 — **regular** (body/labels/captions/readouts) and **semibold** (title/headings), both Streamlit defaults. No custom weight overrides.

Body line-height: Streamlit default (~1.6, close to the 1.5 recommendation) — accepted as-is, no override.
Heading line-height: Streamlit default (~1.2) — accepted as-is, no override.

## Color

Applied via `.streamlit/config.toml` `[theme]`. The sidebar (config form) is the natural **secondary** surface; Streamlit gives it `secondaryBackgroundColor` automatically. Values below are Streamlit's light "engineering-neutral" defaults, declared explicitly so they are a contract the checker can verify, not left to chance.

| Role               | `config.toml` key          | Value                              | Usage                                                                                                   |
| ------------------ | -------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Dominant (60%)     | `backgroundColor`          | `#FFFFFF`                          | Main panel background / plot canvas surface                                                             |
| Secondary (30%)    | `secondaryBackgroundColor` | `#F0F2F6`                          | Sidebar (device config form), input backgrounds, config-summary containers                              |
| Accent (10%)       | `primaryColor`             | `#1F6FEB` (calm engineering blue)  | See reserved-for list below                                                                             |
| Text               | `textColor`                | `#1A1A1A`                          | Body text (near-black for max legibility / correctness reading)                                         |
| Warning (semantic) | native `st.warning` amber  | `#FAA000` family (Streamlit-owned) | Data-blocked / caution banners (e.g. Phase 41 kappa banner); reserved for downstream, contract set here |
| Error (semantic)   | native `st.error` red      | `#D32F2F` family (Streamlit-owned) | Out-of-range / invalid input feedback                                                                   |

**Accent (`primaryColor`) reserved for — explicit list, never "all interactive elements":**

- The active navigation page indicator in the `st.navigation` sidebar list.
- Focused/active form input outlines (Streamlit applies `primaryColor` to the focused widget).
- The primary "Run simulation" button — **Phase 39+ only** (no Run button exists in Phase 38; the sidebar is reactive and needs no submit CTA).

Semantic colors are **correctness-signaling**, not destructive: **warning (amber)** for data-blocked / caution states, **error (red)** for invalid input. There are **no destructive actions** in this phase (device config is overwritten in place, never deleted), so no destructive color is used.

## Navigation & Page Contract (interaction)

**Nav pattern:** `st.navigation({...}) ` + `st.Page(...)` in the entry script `app/main.py`. The device-config sidebar renderer is called in the entry script **before** `pg.run()`, so it renders on every page automatically (satisfies UI-02 "on any page" and UI-07 "persist across nav"). Do **not** use the legacy `pages/` magic directory (it is ignored once `st.navigation` runs).

**Focal point (primary screen — Home):** the user's eye should land first on the **sidebar device-config form** (expanded by default). This is the app's single required action — no workflow page is usable until a device is configured — so the form is the deliberate visual anchor on Home, with the main panel serving only a brief orientation line plus the config summary readout.

**Page list — register all 7 workflow pages as placeholders now** (UI-01: "all simulation workflow pages listed"). Keep the registration list easy to append to (Phases 39–42 fill in behavior). A landing **Home** page is optional but recommended as the default nav target.

| Nav order | Page title              | Icon (Material shorthand / emoji) | Arrives in phase                                                                                                       |
| --------- | ----------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 0         | Home                    | `:material/home:`                 | 38 (this phase — brief orientation + config summary)                                                                   |
| 1         | C-V Analysis            | `:material/show_chart:`           | 39                                                                                                                     |
| 2         | Charge Collection (CCE) | `:material/bolt:`                 | 39                                                                                                                     |
| 3         | Field Map               | `:material/map:`                  | 39 (2D/1D geometry viewer is a **component on this page**, Phase 40 — **not** a separate nav entry, per Phase 40 SC-1) |
| 4         | Radiation Damage        | `:material/warning:`              | 41                                                                                                                     |
| 5         | Dark Current            | `:material/dark_mode:`            | 41                                                                                                                     |
| 6         | Microdosimetry          | `:material/scatter_plot:`         | 42                                                                                                                     |
| 7         | Batch Sweep             | `:material/stacked_line_chart:`   | 42                                                                                                                     |

Icons are discretionary defaults — the executor may substitute equivalent Material Symbols. Grouping via `st.navigation({"Section": [...]})` is optional; a flat list is acceptable for 7+Home pages.

**`st.set_page_config`** (called first in `app/main.py`, before any other Streamlit call):

- `page_title="petringa — SiC TCAD Simulator"`
- `page_icon=":material/memory:"` (chip icon) or emoji fallback
- `layout="wide"` — a scientific tool with wide plots and a persistent config sidebar benefits from full width. Confirmed against the design-spec layout sketch (sidebar + wide main panel).
- `initial_sidebar_state="expanded"` — the config form must be visible on first load.

**Empty-state guard contract (success criterion 4 — every downstream page MUST implement this):**

```python
cfg = st.session_state.get("device_config")
if cfg is None:
    st.info("Configure a device in the sidebar to begin.")
    st.stop()
```

Because the entry-script sidebar always writes `device_config` before `pg.run()`, this normally never fires — but it is **required** by SC-4 and defends against edge cases. No page may crash on empty `st.session_state`.

## Sidebar Device-Config Contract (interaction + copy)

Rendered by a single function (e.g. `render_device_sidebar()`) called in the entry script. **Not** wrapped in `st.form` — the two mode selectors must be reactive so conditional fields appear/disappear immediately. The assembled `DeviceConfig` is stored under the single non-widget key `st.session_state["device_config"]` (the downstream contract for Phases 39–43). Read all 11 fields from `petringa.DeviceConfig` — never redefine them in the app.

**Field grouping** (each group headed by `st.sidebar.header` — the single section-heading primitive — separated by `st.sidebar.divider()`):

### Group 1 — Mode selectors (REACTIVE, render first, outside any form)

| Control        | Widget                                                          | Options / default | Gates                                                                                                                   |
| -------------- | --------------------------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Dimensionality | `st.sidebar.radio("Dimensionality", ["1D", "2D"])`              | default "1D"      | "1D" → `half_width_um=None`; "2D" → show Half-width field                                                               |
| Doping profile | `st.sidebar.selectbox("Doping profile", ["graded", "uniform"])` | default "graded"  | "graded" → show N_D junction/bulk + transition; `N_D=None`. "uniform" → show N_D; graded triplet falls back to defaults |

### Group 2 — Geometry

| Field                    | Label (with unit)          | Widget                           | Default | Visibility                        |
| ------------------------ | -------------------------- | -------------------------------- | ------- | --------------------------------- |
| `epi_thickness_um`       | "Epi thickness (µm)"       | `st.number_input(min_value=0.1)` | 10.0    | always                            |
| `substrate_thickness_um` | "Substrate thickness (µm)" | `st.number_input(min_value=0.0)` | 1.0     | always                            |
| `half_width_um`          | "Half-width (µm)"          | `st.number_input(min_value=0.1)` | 50.0    | **only when Dimensionality = 2D** |

### Group 3 — Doping

| Field             | Label (with unit)        | Widget                           | Default | Visibility                      |
| ----------------- | ------------------------ | -------------------------------- | ------- | ------------------------------- |
| `N_A`             | "N_A substrate (cm⁻³)"   | `st.number_input(format="%.3e")` | 1e19    | always                          |
| `N_D`             | "N_D uniform (cm⁻³)"     | `st.number_input(format="%.3e")` | 1e15    | **only when profile = uniform** |
| `N_D_junction`    | "N_D junction (cm⁻³)"    | `st.number_input(format="%.3e")` | 2.93e15 | **only when profile = graded**  |
| `N_D_bulk`        | "N_D bulk (cm⁻³)"        | `st.number_input(format="%.3e")` | 8.82e13 | **only when profile = graded**  |
| `L_transition_um` | "Transition length (µm)" | `st.number_input(min_value=0.0)` | 0.987   | **only when profile = graded**  |

### Group 4 — Operating conditions

| Field      | Label (with unit) | Widget                           | Default | Visibility |
| ---------- | ----------------- | -------------------------------- | ------- | ---------- |
| `T`        | "Temperature (K)" | `st.number_input(min_value=1.0)` | 300.0   | always     |
| `area_cm2` | "Area (cm²)"      | `st.number_input(format="%.3e")` | 1e-4    | always     |

**Formatting rule (correctness signaling):** every doping and area field uses `format="%.3e"` (scientific notation) so values spanning 1e13–1e19 render and enter cleanly. Every label carries its physical unit in parentheses. This unit-labelling is a hard correctness requirement for a scientific tool, not decoration.

**Conditional field behavior:** when a gated field is hidden, its value is set programmatically (1D → `half_width_um=None`; uniform → graded triplet = defaults; graded → `N_D=None`) so the assembled `DeviceConfig` is always complete and valid regardless of which mode is active.

**Main-panel config summary (Home + placeholder pages):** after the guard passes, render the current config as a monospace readout: `st.json({k: getattr(cfg, k) for k in cfg.__dataclass_fields__})`. This confirms persistence across navigation (UI-07) visually.
