## Trust Boundaries

| Boundary                                                                                    | Description                                                                                                                                                                                                                                                                                                                                                                                                                  | Data Crossing                                                                                                            |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Caller -> `etna` public API (`DeviceConfig`, `build_device`, `run_cv`, `run_field`)     | A local, trusted Python process (a physicist's script, notebook, or test) constructs `DeviceConfig` and calls the facades in-process. There is no network listener, no auth boundary, no remote caller — the caller already has full code-execution privilege equal to etna's own.                                                                                                                                       | Python objects only (dataclass fields: floats, str, Optional[float]); no serialized/untrusted bytes cross this boundary. |
| `etna.api.*` -> `etna.core.*` (devsim)                                              | Facade layer marshals `DeviceConfig` fields (unit-converted) into `etna.core.*` constructors, which drive the `devsim` C++ extension (process-global state).                                                                                                                                                                                                                                                             | Floats/strings only; no file paths, no shell commands, no serialized data.                                               |
| `etna.api.simulation` -> `scipy.interpolate.LinearNDInterpolator` (2D `run_field` only) | New import introduced in this phase (`etna/api/simulation.py:215`). Operates purely on in-memory numpy arrays already produced by devsim; no untrusted input.                                                                                                                                                                                                                                                            | numpy arrays only.                                                                                                       |
| Process-global `devsim` module state                                                        | `reset_devsim_fully()` (called unconditionally at entry to both `run_cv` and `run_field`) enumerates and deletes **every** device registered with devsim in the process, not just etna's own. This is a same-process, same-privilege side effect (not a privilege-boundary crossing) but is a real availability hazard for co-resident code sharing the interpreter (e.g. a notebook, a test harness, an embedding app). | In-process devsim device handles/state only.                                                                             |

No network I/O, no user-authentication, no database, no file loads of untrusted config/data, and no deserialization (`pickle`/`yaml.load`/`eval`/`exec`/`marshal`) exist anywhere in the Phase 36 surface — verified by direct grep across all files added/modified in this phase (see Threat Register evidence column). This is consistent with the project context: etna is an offline scientific library with no network-facing service.
