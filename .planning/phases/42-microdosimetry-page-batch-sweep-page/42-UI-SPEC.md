## Typography

**Inherited verbatim from Phase 38/41.** Exactly 4 sizes (14, 16, 28, 36), exactly 2 weights (regular, semibold). **`st.header` remains the ONLY section-heading primitive** — do not introduce `st.subheader`. **`st.metric` is explicitly NOT used** for the y_F/y_D readouts (see Discretion Resolved below) — it would introduce a large-value rendering size outside the locked 4-size scale, repeating the exact risk Phase 41 avoided by using `st.json`/`st.caption` for all numeric readouts.

| Role             | Streamlit primitive                                      | Size | Weight            | Line Height   |
| ---------------- | -------------------------------------------------------- | ---- | ----------------- | ------------- |
| Page title       | `st.title("Microdosimetry")` / `st.title("Batch Sweep")` | 36px | semibold          | ~1.2 (native) |
| Body / label     | widget labels, `st.write`                                | 16px | regular           | ~1.6 (native) |
| Caption / helper | `st.caption(...)` — CSV format hint, y_F/y_D labels      | 14px | regular           | ~1.5 (native) |
| Numeric readout  | `st.code`/`st.caption` (monospace) — y_F, y_D values     | 14px | regular monospace | ~1.5 (native) |

**Discretion Resolved — y_F/y_D readout widget:** use `st.caption(f"y_F = {result.metadata['y_F']:.2f} keV/µm    y_D = {result.metadata['y_D']:.2f} keV/µm")` (14px monospace-adjacent caption, matching Phase 41's numeric-readout precedent) rather than `st.metric` (which RESEARCH.md's code sketch suggested but which is rejected here — `st.metric` renders large-format numbers that fall outside the exactly-4-size typography contract). Place directly below the spectrum chart.

No `st.header`/`st.subheader` is required on either page — each page has exactly one `st.title` and no sub-sections deep enough to warrant a second heading level. Widget grouping (`st.columns`, `st.expander` labels) substitutes for sub-headings, per Phase 41's precedent.

**Locked demo/default convergence-safe combination (per RESEARCH.md Pitfall 3 — avoid the known `ramp_bias` divergence landmine documented in STATE.md Phase 39):** the page defaults to `sim_label="CCE vs bias (run_cce)"` + `param="epi_thickness_um"` + `values="10, 15, 20"`. A planner Wave-0 live-devsim spike (mirroring Phase 41's own spike) should confirm this exact default combination renders 3 clean/gracefully-truncated overlay curves before the plan locks it in as the shipped default.

## Interaction Contract — Partial Sweep Failure (batch sweep, resolved this session)

**Decision:** if one or more swept values' simulation fails to converge (raises `RuntimeError` from inside the per-value facade call, or `ParametricSweep.run()` surfaces a per-value failure), the page shows a **partial overlay** with the failures noted — it does **not** fail the whole run.

- Iterate `zip(values, sweep_results)`; skip (do not plot) any result with `len(result.x) < 1` or an equivalent empty/failed marker, mirroring the exact aggregation pattern already proven in `app/workflows/dark_current.py` (`T_ok`/`I_total` accumulation loop).
- Track `n_ok` (count of values that produced a plottable result) vs `n_requested` (`len(values)`).
- If `n_ok < n_requested`, show the partial-failure warning banner (Copywriting Contract, above) directly above the chart.
- If `n_ok == 0` (every value failed), do not attempt to render an empty chart — show `st.error("All swept values failed to converge. Try a shallower value range.")` instead and skip the plot/download entirely for that run.
- This mirrors Phase 41's per-temperature dark-current truncation pattern exactly, extended from "per-temperature" to "per-swept-value." A single bad value never crashes the whole sweep — only a `RuntimeError` raised by `ParametricSweep.run()` itself (e.g. an invalid `param`, which the curated selectbox prevents) hits the top-level `try/except RuntimeError` → `st.error` guard.
