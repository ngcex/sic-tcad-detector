<threat_model>

## Trust Boundaries

- browser -> Streamlit page (file upload): the user uploads CSV _bytes_ via `st.file_uploader`. Bytes are untrusted content; the file path is NOT user-supplied (server-generated).
- page -> `run_microdosimetry` (pd.read_csv): uploaded bytes are parsed by `pd.read_csv` only inside `load_mc_events_csv` — pure data, no code execution.

## STRIDE Threat Register

- **T-42-02-T1** — Tampering — uploaded-file path handling — _mitigate_: no path traversal possible; the user supplies bytes only and the temp path is generated by `tempfile.NamedTemporaryFile`. `os.remove` in `finally` guarantees single-request lifetime (T-37-02-V5 alignment).
- **T-42-02-T2** — Tampering / Elevation — CSV content -> code execution — _mitigate_: `load_mc_events_csv` uses `pd.read_csv` only — no eval, no pickle, no binary deserialization. `st.file_uploader(type=["csv"])` restricts the accepted extension. CSV bytes are pure data.
- **T-42-02-D1** — Denial of Service (local) — malformed CSV / degenerate SV inputs — _mitigate_: malformed CSV caught via `try/except (ValueError, KeyError)` -> `st.error`, no crash. SV geometry via `st.number_input` type coercion. run_microdosimetry is a pure pipeline (no solver divergence).
- **T-42-02-D2** — Denial of Service (local) — temp-file disk exhaustion over many uploads — _mitigate_: `os.remove` in `finally` on every run — temp file never outlives the request; no accumulation.
- **T-42-02-SC** — Tampering — npm/pip/cargo installs — _mitigate_: no package installs this phase (RESEARCH Package Legitimacy Audit: zero new packages). Planner must not invent an install task.
  </threat_model>
