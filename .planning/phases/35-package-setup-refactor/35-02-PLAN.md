Note on items 1-2: mock.patch resolves the string as a dotted module path at runtime.
If not updated, the mock silently does not apply — the test may pass for the wrong reason
(no mock applied) or fail with ModuleNotFoundError. `assert mock_itg.call_count == 1`
assertions will give false results if the patch target is stale.

producing petringa/core/src/device.py instead of petringa/core/device.py — no error is raised.

`test ! -d petringa/core && echo "OK to git mv" || echo "ABORT: petringa/core exists"`.

After git mv, re-run editable install: `uv pip install -e ".[dev]"`. This is one cheap step
that ensures hatchling's editable entry point resolves petringa/core/ correctly regardless of
whether the editable mode uses a .pth file or a strict redirector.
