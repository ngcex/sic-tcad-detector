<objective>
Close the single verified gap in Phase 38 (Success Criterion 3 / UI-07): the very first sidebar edit a user makes after a cold app load is silently discarded on the next Streamlit rerun.

Root cause (from 38-VERIFICATION.md, directly reproduced): app/pages/ is a directory literally named pages sitting next to app/main.py. Streamlit legacy magic multi-page auto-detection treats it as a magic pages directory, colliding with the explicit st.navigation API in app/main.py. This destabilizes Streamlit implicit per-widget ID computation across the transition from script-run 1 (boot) to script-run 2 (first rerun). Because no sidebar widget carries an explicit key, any edit bound on run 1 targets a widget ID that no longer exists on run 2 and reverts to its hardcoded default.

This is a minimal, surgical fix: rename the directory, fix all references, add explicit widget keys as defense in depth, and add regression tests that prove the transient is closed at the real-app-structure level.

Purpose: Deliver the UI-07 persistence contract that Phases 39-43 consume via st.session_state device_config.
Output: Renamed app/workflows/ package, updated imports, keyed sidebar widgets, first-rerun regression test plus structural guard test.

Scope constraint (do NOT exceed): Do NOT touch DeviceConfig, physics code, or anything outside the app/ shell and its tests. Do NOT re-plan Success Criteria 1, 2, or 4 (already verified passing). Do NOT change any page module render function name, the empty-state guard text, the st.session_state device_config key name, or the url_path values in app/main.py (those are browser URL segments, unrelated to the directory name).

Mapping to VERIFICATION.md missing list: item 1 (rename away from a pages-named dir) is Task 2 step 1; item 2 (prove the transient is closed, not just the rename) is satisfied by test_first_edit_survives_rerun (value survival across run 1 to run 2) plus test_no_magic_pages_directory (root-cause guard), chosen over re-running the raw proto.id check because the structural guard is what protects the actual root-cause fix (the directory rename, which is empirically the load-bearing change against the real app) from silent regression, independent of whether widget keys are also present; item 3 (human browser confirm) is Task 3.
</objective>
