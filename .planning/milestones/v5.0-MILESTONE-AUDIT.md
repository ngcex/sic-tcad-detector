## SC4 Reinterpretation: Per-File/Per-Class Test Isolation

Success Criterion 4 states that a final `pytest -q` run passes all tests. This is a **documented
reinterpretation** of SC4, not an unqualified claim that the literal single-process invocation was
satisfied verbatim.

**Finding:** bare single-process `pytest -q` is proven unsatisfiable on this machine due to devsim
resource exhaustion — this reproduces even on the pre-refactor commit `fe3b43c` (see
`35-02-SUMMARY.md`), so it is a pre-existing environmental limitation, not a regression introduced
by any v5.0 phase. The established project convention (PKG-03) is **per-file/per-class test
isolation**: run DD-heavy devsim test modules individually rather than combined in one process.

**Dependency decision:** `pytest-forked` (which would subprocess-isolate each test and could allow
a single literal `pytest -q` command to pass) was **explicitly rejected** for this phase — no new
dependencies are permitted in an audit phase, and the package was never verified for legitimacy.

**Task-1 evidence (this phase, 2026-07-15):**
