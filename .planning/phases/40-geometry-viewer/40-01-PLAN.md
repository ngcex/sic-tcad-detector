From etna/api/results.py (re-exported at top level: `from etna import MeshData`):

```python
@dataclass
class MeshData:
    x_coords: np.ndarray            # node x coordinates (cm)  — CM, not µm
    y_coords: "np.ndarray | None"   # node y coordinates (cm), None for 1D
    node_values: dict[str, np.ndarray]  # keys: "NetDoping", "Potential", "ElectricField"
    regions: list[dict]             # [{name, x_min, x_max, y_min, y_max}] (cm)
    contacts: list[dict]            # [{name, position}]
```

Units fact (load-bearing): `x_coords`/`y_coords` are in CM. The viewer MUST convert to µm by multiplying by `1e4` before building axes. (Contrast: `results.build_field_figures` uses `result.x` which is ALREADY µm — this viewer is the opposite and must NOT reuse that assumption.)
</interfaces>
