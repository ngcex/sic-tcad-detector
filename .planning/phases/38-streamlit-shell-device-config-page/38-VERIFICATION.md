### Cross-check against 38-REVIEW.md (WR-01)

The code review (38-REVIEW.md) flagged WR-01 as scoped to conditionally-rendered (mode-toggle-gated) fields only (`half_width_um`, `N_D`, `N_D_junction`, `N_D_bulk`, `L_transition_um`), explicitly stating "plain page navigation and unrelated-widget reruns were separately verified to preserve values correctly, so UI-07 persistence-across-navigation itself is intact."

Independent re-verification found this framing incomplete: the defect is not scoped to gated fields, and it is not a mode-toggle-specific issue. It is a **first-rerun widget-ID instability affecting every sidebar widget** (confirmed on `epi_thickness_um`, a plain always-visible, non-gated field), rooted in the `app/pages/` legacy-magic-directory collision with `st.navigation`, not in the gated-field rendering pattern WR-01 attributes it to. The review's practical symptom (mode-toggle round-trips losing values) is a real manifestation of the same root cause, but the review under-scoped the blast radius and mis-attributed the mechanism (missing `key=` args is a contributing factor, but the deeper trigger is the `pages/` directory name collision destabilizing Streamlit's implicit ID derivation on the first rerun — adding explicit `key=` alone, as WR-01's suggested fix proposes, would very likely close the symptom without addressing why the ID shifts in the first place, though it was not tested here).

## Gaps Summary

Three of the four ROADMAP success criteria are solidly verified: the app boots and lists all pages (Criterion 1), the sidebar exposes all 11 `DeviceConfig` fields as interactive controls (Criterion 2), and every page guards against an empty `st.session_state` (Criterion 4).

Criterion 3 — "A DeviceConfig assembled from the form values is stored in st.session_state and remains intact after navigating to a different page and returning" — fails under direct reproduction. The failure is deterministic and traced to root cause: `app/pages/` is a directory literally named `pages`, sitting next to `app/main.py`, which Streamlit's legacy multi-page auto-detection treats as a magic pages directory, colliding with the explicit `st.navigation` API also used in `app/main.py`. This collision destabilizes Streamlit's implicit per-widget ID computation specifically across the transition from the very first script execution to the first rerun. Because no sidebar widget in `app/components/device_sidebar.py` carries an explicit `key=`, every widget's persisted value is silently lost if the user's first edit happens to land on that one-time unstable transition — the most likely moment for a first-time user to make their first edit.

The existing code review (38-REVIEW.md, WR-01) identified a related symptom but scoped it incorrectly to mode-toggle-gated fields only and concluded that "UI-07 persistence-across-navigation itself is intact." Independent verification found the defect is broader (affects any sidebar field, not just gated ones) and is not a navigation-specific issue in the sense the review implies — it is a first-rerun-only transient that, once passed, does allow correct persistence across further navigation. This nuance does not reduce the severity for Criterion 3: `device_config` is the exact contract Phases 39–43 are built to consume (per both plans' "Next Phase Readiness" sections), and a defect that can silently drop a user's very first configuration edit is a direct, reproducible violation of the roadmap's stated success criterion.

**This looks unintentional** — no override is being suggested. The plans explicitly called out avoiding the legacy `pages/` magic directory for routing purposes, and the executor satisfied the letter of that instruction (using explicit `st.Page` callables, not string paths) without catching that the directory's _name_ alone still triggers the collision independent of how it's used for routing.
